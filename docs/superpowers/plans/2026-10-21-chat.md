# Chat entre cliente e chef Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Conversa por par cliente-chef (o cliente inicia), mensagens de texto com editar, apagar, denunciar e "visto", entregues em tempo real por SSE, com as denúncias indo para a fila e a auditoria da moderação.

**Architecture:**
- Tabelas novas na `V3__chat.sql`.
- O `ChatService` concentra as regras: participante, autor, prazo de edição e destinatário.
- As denúncias de mensagem reaproveitam `StatusDenuncia`, o `ModeracaoRegistry` e a auditoria `acao_moderacao`.
- Os serviços publicam eventos; um `TempoRealListener` com `AFTER_COMMIT` empurra pelo `SseRegistry`. As notificações entram na mesma transação, como já acontece hoje.

**Tech Stack:** Java 17, Spring Boot 4.0.5, Spring MVC `SseEmitter`, Spring Security 7, JPA, Flyway (`V3`), H2 e Testcontainers (Postgres 17).

**Spec:** `docs/superpowers/specs/2026-10-21-chat-design.md` (v2)

## Global Constraints

- **Rotas e papéis:**
  - `POST /conversas` → `hasRole(CLIENTE)`;
  - `/conversas/**` → `hasAnyRole(CLIENTE, CHEFE)`, porque moderador não conversa;
  - `/eventos` → qualquer autenticado;
  - `/moderacao/denuncias-mensagens/**` já está coberto por `/moderacao/**`.
- **Status de erro:**
  - conversa que não existe ou da qual não participo → **404**;
  - editar ou apagar mensagem de outra pessoa → **404**;
  - editar depois de **15 minutos**, ou editar uma apagada → **409**;
  - denunciar a própria mensagem → **404**;
  - denúncia repetida da mesma mensagem → **409**;
  - denunciar mensagem apagada → **409**;
  - chef apagado ou banido no envio (remetente ou destinatário) → **403** (`ContaInativaException`);
  - texto em branco ou com mais de 2000 caracteres → **400**.
- **Textos:**
  - notificação de mensagem: `"Nova mensagem de {nomeRemetente}"`, com `referenciaId` igual ao id da conversa, criada **só se** não existir `MENSAGEM_RECEBIDA` não lida com a mesma referência para o mesmo destinatário;
  - notificação de denúncia: `"Nova denúncia de mensagem ({MOTIVO})"`, com `referenciaId` igual ao id da denúncia, para cada moderador;
  - prévia da última mensagem: até 100 caracteres.
- **Enums novos:**
  - `MotivoDenunciaMensagem`: `OFENSIVA`, `ASSEDIO`, `SPAM`, `GOLPE`, `CONTEUDO_IMPROPRIO`, `OUTRO`;
  - `EventoNotificacao` ganha `MENSAGEM_DENUNCIADA`;
  - `TipoAcaoModeracao` ganha `ARQUIVAR_DENUNCIA_MENSAGEM` e `REMOVER_MENSAGEM`.

  A `V3` atualiza os CHECKs de `notificacao.evento` e `acao_moderacao.acao`, e o teste de CHECKs de enum obriga isso.
- **Eventos SSE:**
  - `mensagem` (`MensagemDto` do ponto de vista de quem recebe);
  - `mensagem_editada` (`MensagemDto`);
  - `mensagem_apagada` (`{conversaId, mensagemId}`);
  - `mensagens_lidas` (`{conversaId, ateId, lidaEm}`);
  - `notificacao` (`{total}`).

  O envio acontece **sempre depois do commit**.
- **Privilégio mínimo:** a `V3` não precisa de `REVOKE`, porque mensagens e denúncias de mensagem mudam de estado e a API precisa de `UPDATE`. A auditoria continua só de inserção.
- Testes: `./mvnw -q clean test -Dspring.profiles.active=test`, com o Docker ligado. Para contar, some os atributos `tests`, `failures`, `errors` e `skipped` **pelo nome**. Os testes de integração limpam o H2 na ordem das chaves estrangeiras: `denuncia_mensagem` → `mensagem` → `conversa` → demais.
- **Não commitar** `src/main/resources/application-prod.yml`. Commit sempre por caminho, e os commits terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Duas abas abertas do mesmo usuário:** as duas recebem o evento `mensagem`, e uma aba que caiu é descartada sem quebrar o envio para as outras. Teste na Task 5.
2. **Mensagem editada ou apagada depois de denunciada:** a moderação continua vendo o **texto original** da denúncia. Teste na Task 4.
3. **Dez mensagens seguidas sem leitura:** uma única notificação. Depois de `PATCH /lidas`, a próxima mensagem gera uma nova. Teste na Task 2.
4. **Cliente com conversas, mensagens e denúncias de mensagem apaga a conta:** responde 204 e tudo some, sem violar chave estrangeira. Teste na Task 6.
5. **Erro ao enviar pelo SSE**, por exemplo cliente desconectado: não desfaz a mensagem gravada e não devolve 500 ao remetente. Teste na Task 5.
